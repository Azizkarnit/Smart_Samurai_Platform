# ⚔️ Path of the Samurai — Live Robot Competition Platform

A full-stack, real-time robot competition management system built for **ISTIC MakerLabs**. Physical sensors on an ESP32 detect each challenge completion and send data to InfluxDB; a live web dashboard streams results to the audience, and a final results page ranks all competitors by a weighted formula.

> **This is the complete production system.** The Python `main.py` is a manual CLI fallback for testing without hardware.

## ⚙️ Prerequisites

### Software
| Tool | Version | Install |
|---|---|---|
| Python | 3.8+ | [python.org](https://python.org) |
| InfluxDB | v2.x | [influxdata.com](https://www.influxdata.com/downloads/) |
| Arduino IDE | 2.x | [arduino.cc](https://www.arduino.cc/en/software) |
| ESP32 Board Package | latest | Arduino IDE → Boards Manager → search `esp32` by Espressif |

### Python packages
```bash
pip install flask influxdb-client supabase
```

### InfluxDB setup (one time)
1. Download and install InfluxDB v2
2. Open `http://localhost:8086` and create:
   - **Organisation:** `istic`
   - **Bucket:** `makerlabs`
   - **API Token:** copy it and paste it in `server.py`, `main.py`, and the Arduino sketch
3. Enable CORS (required for the browser to query InfluxDB directly):

**Windows — set permanently via System Environment Variables:**
```
INFLUXD_HTTP_CORS_ENABLED = true
INFLUXD_HTTP_CORS_ORIGINS = *
```
Then restart InfluxDB.

## 🚀 How to Run — Step by Step

### Step 1 — Prepare player data

**Option A — fetch from Supabase (production):**
```bash
python fetch_homologation.py
```
This connects to Supabase, shuffles the player order randomly, and writes `homologation.csv`.

**Option B — edit manually:**
Edit `homologation.csv` directly. Format:
```csv
id_robot,Leader_name,Robot_name,Nom_club,homologation_score
1,adhar_sebei,hobel,z,5
2,khadija,yayo,o,6
...
```

---

### Step 2 — Start InfluxDB
```bash
# Windows (in its installation folder)
influxd

# Or if you set the CORS env vars, just run it normally
```

---

### Step 3 — Start the Flask server
```bash
python server.py
```
Output:
```
[server] CSV cleared → leaderboard.csv
[server] Dashboard → http://localhost:5000/
[server] Place video → static/robot_run_record.mp4
```

> ⚠️ Place your pre-recorded run video at `static/robot_run_record.mp4` before starting.

---

### Step 4 — Open the dashboard
In a browser on the display machine:
```
http://localhost:5000/
```
Or from another machine on the same network:
```
http://192.168.1.X:5000/
```

---

### Step 5A — Hardware mode (ESP32)

**Configure the sketch** before uploading:
```cpp
// path_of_samurai_v2.ino
const char* WIFI_SSID   = "YOUR_WIFI_SSID";
const char* WIFI_PASS   = "YOUR_WIFI_PASSWORD";
const char* INFLUX_HOST = "192.168.1.X";   // IP of the PC running InfluxDB
```

Upload to ESP32 via Arduino IDE. The ESP32 handles everything — no Python needed during the actual competition.

---

### Step 5B — Manual CLI mode (no hardware / testing)
```bash
python main.py
```

If a previous session was saved, it resumes from the last player. To start fresh:
```bash
# Inside the CLI, type:
resetall
# then confirm: yes
```

**Available commands:**
| Command | Action |
|---|---|
| `start` | Register next player |
| `dep` | Start the run (timer begins) |
| `chall1` – `chall5` | Confirm challenge 1–5 (+20 pts each) |
| `fin` | Same as `chall5` (same sensor) |
| `disq` | Disqualify current run immediately |
| `resetall` | Wipe all data and start fresh |

## 🏆 Final Results Page

Press **`L`** on the dashboard to open the final results page in a new tab.

**Ranking formula:**
```
Score Général = 0.43 × H  +  0.2 × S  +  0.37 × (S / T)

  H  =  homologation score (from homologation.csv, scale 0–10)
  S  =  run score in points (max 100)
  T  =  run time in seconds
```

- Each player's **best Score Général** across both runs is used
- Top 3 are revealed with a samurai-themed animation: 🥉 → 🥈 → 🥇
- Ranks 4+ appear in a table below the podium

## 🤖 ESP32 Hardware — Pin Reference

### `path_of_samurai_v2.ino`

| GPIO | Component | Function |
|---|---|---|
| 4 | Button — START | Register next player |
| 5 | Button — DISQ | Disqualify active run |
| 18 | Button — DEP | Clear InfluxDB database |
| 19 | Button — OVERRIDE | Manually confirm current challenge |
| 26 | Sensor S1 | **DEP** trigger (1st pass) + **C5 + FIN** (2nd pass) |
| 23 | Sensor S2 | Challenge 1 |
| 25 | Sensor S3 | Challenge 2 |
| 21 | Sensor S4 | Challenge 3 |
| 22 | Sensor S5 | Challenge 4 |
| 2 | LED | Feedback blinks |

### Blink patterns
| Pattern | Meaning |
|---|---|
| 1 blink | Challenge confirmed |
| 2 blinks | Player registered (START) |
| 3 blinks | WiFi connected |
| 4 blinks | Disqualified |
| 5 blinks | Run complete / DB cleared |
| 3× fast | Error / rejected action |

### Sensor wiring
All sensors and buttons use **INPUT_PULLUP** — wire one side to GND, other to GPIO. Active LOW (trigger = connect to GND).

## 🔄 Competition Flow

```
fetch_homologation.py       ← run once before the event
        │
        ▼
   homologation.csv          ← randomised player order
        │
        ▼
  python server.py           ← keep running all day
        │
        ▼
  Browser → localhost:5000   ← open on projector screen

── PER ROBOT ──────────────────────────────────────────

  ESP32: press START         → registers player, dashboard shows name
  Robot placed at start line
  Robot crosses Sensor 1     → DEP fires, timer starts, video plays
  Robot crosses Sensor 2     → Challenge 1 ✅
  Robot crosses Sensor 3     → Challenge 2 ✅
  Robot crosses Sensor 4     → Challenge 3 ✅
  Robot crosses Sensor 5     → Challenge 4 ✅
  Robot crosses Sensor 1 again → Challenge 5 + FIN ✅ → run saved
         │
         ├── OR: press DISQ at any point → disqualified, run saved
         │
         └── OR: press OVERRIDE to manually confirm a challenge

── AFTER ALL ROBOTS ────────────────────────────────────

  Press R on dashboard       → switch to Run 2 (or auto-switches)
  Repeat for all players

── FINAL RESULTS ───────────────────────────────────────

  Press L on dashboard       → opens final_results.html
  Animation reveals Top 3 → Full ranking by Score Général
  Press P on dashboard       → exports runs.csv
```

## 💾 Crash Recovery

If `server.py` or `main.py` crashes mid-competition:

1. **Run data** is backed up to `localStorage` in the browser after every run
2. **Player state** is saved to `robot_state.json` after every run
3. On restart, `server.py` reads `leaderboard.csv` (already saved); the browser reloads data from the server automatically
4. `main.py` reads `robot_state.json` and resumes from the correct player ID

To fully wipe and restart:
- In CLI: type `resetall` → confirm `yes`
- In browser: press `C` → confirm
